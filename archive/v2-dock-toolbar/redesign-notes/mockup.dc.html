Screen Annotator Pro · v3.0.1 · interface study

One row, not one column.

The tools are good. The panel is the problem: a 900-pixel column of text rows that covers a fifth of the screen you are trying to annotate, with every control visible at once whether the active tool uses it or not. Here it is rebuilt as a single dock — tools always, options only when they apply.

What changed, and why

01

Horizontal, not vertical

Screens are wide and content is tall. A 940px column sits directly on top of the document being annotated; a 112px dock at the bottom edge sits on top of almost nothing.

02

Options follow the tool

Colour, stroke and opacity are shown when the active tool uses them. Black Box has no colour; Blur has no stroke. The second row rewrites itself instead of showing every control at all times.

03

Icons carry the shortcut

Text labels made 17 tools into a scrolling list. Icons with the key printed in the corner fit on one line and teach the keyboard, which is how the app is meant to be driven.

04

No collapsible sections

Draw, Annotate and Redact become three groups divided by rules — visible at a glance, no expand step, no state to remember between sessions.

05

One consistent icon set

Emoji (📷 ⏸ 🗑) render differently on every Windows build and clash with the text glyphs beside them. One stroked set at one weight reads as a product rather than a script.

06

Destructive actions set apart

Undo, redo and clear move into a tinted cell behind a rule, away from the tools. Exit is the only red-filled control on the dock, at the far end.

Everything here maps onto the existing PyQt6 structure — the same tool ids, the same shortcut keys, the same settings. What changes is the layout of Toolbar and which property widgets are shown for the active tool.
